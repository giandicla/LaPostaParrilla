## 1. El pedido inicial

El usuario pidió una página web para el restaurante familiar **La Posta**, en Villa
La Angostura, como trabajo práctico de Programación Web. Aportó:

- El logo en baja resolución (`LogoLaPosta.jpg`, 150×150px).
- El Instagram: `@lapostavla`.
- El link de la carta en Canva.
- El repositorio destino, vacío: `github.com/giandicla/LaPostaParrilla`.
- Las consignas del profesor: convertir todo a React, crear cuenta en Vercel,
  enlazarla con GitHub, y aclararle a la IA "solo hacé el React del front".
- El pedido explícito de llevar archivos `.md` de contexto para que un chat nuevo
  entienda el proyecto.

Dijo también que el color característico es bordo y que el lugar es de madera,
acogedor.

## 2. Lo primero que hizo la IA: no escribir código

En vez de empezar a programar, el asistente:

1. **Midió el color real del logo** con un script, en vez de estimarlo a ojo.
   Resultado: `#5F0004` exacto. Ese valor es el que gobierna toda la paleta del sitio.
2. **Clasificó el trabajo como "arquitectural"** y siguió un proceso de diseño antes
   de implementar: preguntas → diseño → especificación escrita → plan → ejecución.
3. **Hizo cuatro preguntas** que cambiaban materialmente el resultado: stack, manejo
   de datos, secciones, y estilos.

El usuario respondió que por ahora quería **solo la visual**, sin lógica de datos.

**Decisión de diseño resultante:** Vite + React + React Router, CSS Modules, y el
formulario de reservas como maqueta sin persistencia.

## 3. El descubrimiento que reorganizó el proyecto

Al escribir la especificación, el asistente marcó como dato faltante: *"si son dos
locales distintos — el usuario mencionó «ambos restaurantes»"*. Y avisó que si eran
dos, eso cambiaba la navegación del sitio entero.

El usuario confirmó: **son dos locales bajo la misma marca**, con cartas distintas.

Se evaluaron tres formas de dividir el sitio:

| Patrón | Resultado |
|---|---|
| **A — Un sitio, dos salones** | **Elegido.** Una sola home; la división aparece solo donde cambia la información |
| B — Hub con sub-sitios por local | Descartado: casi el doble de trabajo y obliga a elegir antes de ver nada |
| C — Selector global persistente | Descartado: solo sirve si el contenido es casi idéntico |

**La consecuencia técnica es la decisión más importante de todo el proyecto:** los
locales son **datos, no rutas**. Un array `LOCALES` en `src/data/locales.js`, y todos
los componentes iteran sobre él o reciben un local por props. Sumar un tercer local
es agregar un objeto al array.

Esto se convirtió en una regla verificable por comando:

```bash
grep -rn "'parrilla'\|\"parrilla\"\|'restaurante'\|\"restaurante\"" src/ app/ --include=*.jsx
```

Debe devolver cero resultados. Se corrió en todas las tareas posteriores.

## 4. Método de trabajo

Se escribió un **plan de implementación de ~4600 líneas** con el código real de cada
archivo, dividido en 14 tareas. Después se ejecutó así:

1. Un **subagente implementador** por tarea, con instrucciones acotadas.
2. Un **subagente revisor** por tarea, que verifica contra la especificación.
3. Si la review encuentra algo, un **ciclo de corrección** y una re-review acotada.
4. Un **ledger** que registra cada decisión, para sobrevivir a la pérdida de contexto.

Los chequeos que requerían navegador no se pudieron hacer: ningún agente puede
abrir uno. Se reemplazaron por lectura de código contra criterios explícitos, más
verificaciones por `grep` y por build.

## 5. Los dos cambios de rumbo del usuario

### 5.1 El profesor exigió Next.js

Con **seis tareas ya implementadas en Vite**, el usuario avisó que el profesor
definió que el proyecto tiene que ser Next.js.

**Decisión: migrar en ese momento, no al final.** El razonamiento: lo caro (capa de
datos, tokens de diseño, CSS Modules) pasa a Next sin cambios; lo que se reescribe es
solo el ruteo. Migrar después de ocho tareas más habría significado escribir cada
página dos veces.

Sobrevivió sin tocarse: `src/data/` entero, `tokens.css`, `global.css`, y todos los
CSS Modules de componentes.

Se reescribió: `index.html` → metadata en `app/layout.jsx`; `createBrowserRouter` →
carpetas en `app/`; `<Link to>` de React Router → `next/link`; el redirect de ruta
desconocida → una página 404 real.

La especificación se **enmendó** en vez de reescribirse: Vite quedó en "Rechazadas"
con el motivo real —no fue técnico, fue la consigna— y se agregó una sección
documentando qué sobrevivió y qué cambió.

### 5.2 Vercel bloqueó el deploy

Vercel rechazó el despliegue con *"the commit author did not have contributing access
to the project"*.

**Causa:** los commits estaban firmados con `gianfrancodicla@gmail.com` (cuenta
personal), pero el repositorio pertenece a `giandicla`, la cuenta de la facultad, con
el mail `gdiclaudio@itba.edu.ar`. El asistente había tomado el mail de la
configuración de Claude Code sin preguntar cuál correspondía.

**Solución:** se corrigió la identidad del repositorio y se reescribió la autoría de
los 13 commits existentes, verificando antes que el contenido fuera idéntico al
respaldo. Se guardó un tag local `respaldo-antes-de-reescribir-autoria` por si algo
salía mal.

## Adenda — 2026-09-29: la revisión general

La sesión se cortó por límite de uso antes de correr la revisión general de la rama.
Al retomarla, encontró **un bug Critical y cuatro Important** que las catorce
revisiones por tarea habían dejado pasar.

El Critical: **en un celular no se podía cerrar el menú.** Está contado en detalle en
`hallazgos.md` §1.2, porque el caso interesante no es el bug sino que el propio
checklist de pruebas estaba escrito de forma que no se podía encontrar.

Los otros cuatro:

- Los platos destacados de la parrilla eran dos entradas (`hallazgos.md` §1.3).
- El anillo de foco medía 1.89:1 sobre el fondo crema — prácticamente invisible en
  casi todo el sitio. Solo se veía sobre las secciones bordo, que es justo donde el
  checklist mandaba a mirarlo.
- `CLAUDE.md` afirmaba algo falso sobre cómo se usa el componente `Boton`, y es el
  archivo que cualquier chat nuevo carga automáticamente.
- Una expresión regular escrita con dos caracteres Unicode invisibles en vez de sus
  escapes. Funcionaba, pero se corrompe con cualquier normalización y era la línea
  menos explicable del repositorio.

También verificó la promesa central del spec —que sumar un tercer local es solo
agregar datos— y encontró que **era cierta en todo el JavaScript y falsa en el CSS**:
seis reglas asumían "exactamente dos". Se corrigieron, así que ahora la promesa es
literalmente cierta.

Todo se corrigió en el commit `1b70c3d`.

**Lección de método:** las revisiones por tarea y la revisión general encuentran
cosas distintas. Las primeras verifican que cada pieza cumpla lo que se le pidió; la
segunda es la única que puede preguntarse si el conjunto tiene sentido como producto.
Saltearla habría dejado el sitio con un menú que no se puede cerrar en un teléfono.
